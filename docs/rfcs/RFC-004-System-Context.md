# 1. Abstract

This document defines the system boundary of MorphLab and identifies the external actors and systems that interact with the platform.

The purpose of this RFC is to establish a common understanding of what belongs to MorphLab and what remains outside its responsibility.

This document intentionally avoids software architecture and implementation details.

---

# 2. Purpose

MorphLab operates as the central software platform for experimental mechatronics research.

The platform coordinates experiments, communicates with external systems, collects observations, executes analysis workflows, and manages experimental data.

External hardware and software systems interact with MorphLab through well-defined interfaces.

---

# 3. System Boundary

MorphLab is responsible for:

- Experiment management
- Configuration management
- Device integration
- Data acquisition
- State management
- Data synchronization
- Data logging
- Analysis
- Visualization
- Experiment evaluation
- Result generation

MorphLab is **not** responsible for implementing hardware devices, operating systems, embedded firmware, or external software tools.

---

# 4. External Actors

## Researcher

The primary user of MorphLab.

Responsibilities include:

- Designing experiments
- Configuring experiments
- Executing experiments
- Monitoring execution
- Evaluating results

---

## Physical Mechanism

The mechanical system being investigated.

The mechanism is external to MorphLab.

MorphLab observes and controls the mechanism but does not define its mechanical design.

---

## Controllers

Embedded control hardware responsible for low-level interaction with mechanisms.

Controllers execute hardware-specific logic and exchange information with MorphLab.

Controllers remain external systems.

---

## Measurement Systems

Independent systems that provide experimental observations.

Examples include:

- IMUs
- Motion capture systems
- Optical tracking systems
- Mobile devices
- External sensors

MorphLab treats all measurement systems as external observation providers.

---

## Visualization Clients

External applications used to visualize experimental information.

Examples may include desktop applications, web applications, or mobile interfaces.

Visualization clients consume information generated by MorphLab.

---

## Data Consumers

External software responsible for post-processing experimental data.

Examples include:

- Scientific computing environments
- Machine learning frameworks
- Statistical analysis tools
- Publication pipelines

MorphLab provides data but does not control downstream analysis tools.

---

# 5. External Systems

The following systems are considered external to MorphLab.

- Embedded firmware
- Hardware drivers
- Operating systems
- Network infrastructure
- Storage infrastructure
- Simulation software
- CAD software
- Numerical solvers
- Scientific software packages

MorphLab may integrate with these systems without becoming dependent on them.

# 7. Responsibility Model

MorphLab owns:

- Experimental workflows
- Experimental data
- Experimental metadata
- Data synchronization
- Analysis workflows
- Result generation

External systems own:

- Hardware implementation
- Firmware implementation
- Physical sensing
- Physical actuation
- Mechanical behavior
- Operating system services

---

# 8. Design Implications

The system boundary establishes several architectural consequences.

- External hardware shall be replaceable.

- Multiple hardware implementations may coexist.

- Multiple measurement systems may observe the same mechanism.

- Multiple visualization clients may consume the same experimental data.

- Experimental workflows shall remain independent from specific hardware implementations.

---

# 9. Future Extensions

The defined system boundary supports future integration of additional external systems, including:

- Digital Twin platforms
- Hardware-in-the-loop systems
- Software-in-the-loop systems
- Cloud-based execution environments
- Distributed experiments
- Autonomous data analysis systems

These additions should not require redefining the MorphLab system boundary.

---

# 10. Summary

MorphLab acts as the central orchestration platform for experimental research.

It coordinates experiments and manages scientific workflows while remaining independent from specific hardware, firmware, operating systems, and external software tools.

The system boundary defined in this RFC serves as the foundation for subsequent architectural decisions.
